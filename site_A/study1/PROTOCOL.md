# A0 γ0 重跑协议（预注册）

写于 2026-09-29，此时 HyP3 作业还在排队，**尚未看到任何新结果**。执行者：Claude，经用户批准。

## 1. 为什么要重跑

A0 终检稿（`../submission_final_check_20260922/`）的强度数据有两处与正文不符，或者对强度基线不公平：

1. **辐射量混用。** T15/T37 用的是 σ0 dB（HyP3 `sdunem`，DEM matching），T88/T139 是 γ0 功率（`gpuned`）。正文写的是 "terrain-flattened γ0"。
2. **降采样方式不当。** 10 m 到 40 m 是在 dB 域做双线性插值，没有做多视平均。相干性则是 10×2 视估计的。

另外，A0 和 A1 要合并成一篇 TGRS 稿（用户 09-29 决定），所以两部分的处理链需要统一：γ0 功率、线性域面积平均。

## 4. 判读规则（事先写定）

主量 ΔBA = BA(I28+g12) − BA(I28)，跨轨，RF 和 SVC 分别报告，区间来自 20,000 次联合块 bootstrap。

| 结局 | 判据（RF 与 SVC 都满足） | 合并稿中的写法 |
|---|---|---|
| **维持** | ΔBA ≥ 4 pp，且 95% 区间下界 > 0 | 相干性对建成区/森林的边际价值在统一的 γ0 线性处理下依然成立；以新数字替换旧数字 |
| **收缩** | 0 < ΔBA < 4 pp，且区间下界 > 0 | 如实报告缩小后的效应；强调增益随类别变化，叙事重心移向「类别依赖 + 预算衰减」 |
| **消失** | 区间包含 0 | A0 部分改写为「强度处理公平之后两景相干性不再有边际价值」。这本身就是合并稿的一条发现，与 A1 的作物结果一致 |

补充规则：
- 旧数字（v6）一律不再作为主结果。正文与补充材料中所有 A0 数字都从 `ws/tables*` 重新生成。
- 如果 v7 的 Ω 像元中缺失强度的超过 0.1%，就停下来，先核对支持集（s4 会自动检查）。
- S2 与 R1g 的差别只在评估集。两者都报告；主文以哪个为准，等看到建成区的像元数和对象数之后再定，并说明理由。

## 5. 追加实验（用户 2026-09-29 批准），在看到 v7 结果之前写定

### 5.1 CNN 空间上下文基线（`scripts/s10_cnn_baseline.py`）

- **两个分支**：`CNN_I` 用 vv1、vh1、vv2、vh2 四个通道；`CNN_IG` 在此基础上加 g12。
- **输入**：9×9 patch（40 m，半宽 160 m）。在 400 m 缓冲下，训练 patch 和评估 patch 不会重叠。
- **与 R1 相同的部分**：训练像元、评估像元、seed、12 个评估块。评估同时报告每块 800 像元的抽样集和全部 C2 像元。
- **训练设置事先固定**：30 epoch，AdamW，lr 1e-3，wd 1e-4，batch 256，交叉熵，无数据增强，取最后一个 epoch，不根据测试集做任何选择。标准化只用源轨道的训练 patch 来拟合。在 CPU 上训练，模型约 5.8 万参数。
- **主量**：`CNN_IG − CNN_I` 的跨轨 ΔBA；对照量：`CNN_I − RF_I28`。判读规则沿用 §4 的三档（≥4 pp 为维持，0–4 pp 为收缩，区间包含 0 为消失）。
- **如实披露**：写协议前，为了测运行时间，在旧的 v6 立方体上跑过一个冒烟配置（`CNN_IG`，源轨道 T15，seed 17），四个目标轨道的 BA 为 74.9–82.3%。这个数字不进论文，但说明 CNN 可能明显强于 RF，此前的 RF/SVC 基线可能偏弱。所以合并稿里要**同时报告**「相干性在 CNN 下的边际价值」。

### 5.2 同期建成区核查：BAG 建筑登记（`scripts/s9_download_bag.py`，分析脚本随后编写）

- **数据**：PDOK BAG `pand` 是当前登记，许可为 Public Domain Mark。只保留 `bouwjaar ≤ 2024`，且状态为「在用 / 在用（未测量）/ 改建中 / 已发拆除许可 / 停用」的建筑。另外，状态为「已拆除」、但 `documentdatum` 晚于 2024-05-31 的建筑也保留，因为 SAR 采集时它们还在。`documentdatum` 是状态变更文件的日期，可能比实际拆除晚一些。这是一处局限，要写进论文。
- **栅格化**：在 4 m 网格上计算建筑覆盖，再平均到 40 m 像元，得到建筑覆盖比例 f_BAG。
- **范围**：12 个评估块内的全部 Ω 像元，不要求 WorldCover 与 CORINE 一致。
- **检验一（主）**：f_BAG ≥ 0.25 的像元记为「BAG 建成」，在这些像元上比较 I28 与 I28+g12 的建成区召回，报告 RF/SVC 的 Δ 和块 bootstrap 区间。
- **检验二**：离最近建筑 ≥ 80 m 的像元上，模型把像元判为建成区的比例（误报），同样比较 I28 与 I28+g12。
- **描述量**：C2 中建成区标签与 f_BAG 的一致程度。
- **判读**：检验一的 Δ > 0 且区间不含 0，说明建成区增益在同期、独立的标签下仍然成立。检验二里 g12 分支的误报如果显著增加，要写成一条局限。

## 5.3 补充检验（用户 2026-09-30 批准；写于这些检验的结果出来之前）

背景：§5.1 的 CNN 结果（CNN_IG − CNN_I = +1.29 [−1.14, 3.93]）现在承担合并稿的一条主结论，需要排除「CNN 恰好没调好」「patch 大小选得不巧」「seed 太少」这三种解释。

**C1：训练块内调参**（`s13_cnn_checks.py --stage cv`）
- 用 R1 同一组 3 折空间 CV（`source_spatial_cv_3fold`），只在训练块内进行，折间保留 400 m 缓冲，seed 17；按每个分支、每条源轨道分别选参。
- 网格共 12 组：lr ∈ {1e-3, 3e-4} × epochs ∈ {15, 30, 60} × weight decay ∈ {1e-4, 1e-3}。
- 选参标准是 3 折平均 BA 最高；差距在 0.1 pp 以内时取更简单的一组（epoch 少的，其次 lr 大的）。

**C2：seed 增加到 5 个**：17、29、43、53、71。训练像元用 `RandomState(seed)` 从同一缓冲候选集中抽取。

**C3：patch 大小**
- 5×5、9×9、11×11：半宽 ≤ 200 m，在 400 m 缓冲下训练与评估窗口不会重叠。
- 15×15：半宽 280 m，需要把缓冲加到 600 m 才能避免窗口重叠，所以训练集和其他分支不同，只作次要参考。
- C3 用 §5.1 的固定超参和 5 个 seed。

**主量**：C1 选出的超参、9×9 patch、5 个 seed 下的 CNN_IG − CNN_I 跨轨 ΔBA（20,000 次块 bootstrap）。判读沿用 §4 的三档。
- 如果仍判为「消失」，合并稿写「空间上下文基本替代了相干性的整体增益」。
- 如果变成「收缩」或「维持」，就如实改写。
- C3 只报告趋势，不改变主判读。

## 5.4 BAG 敏感性（事后分析，探索性，结论前后都会标注）

- 把 f_BAG 阈值取为 0.25、0.5、0.75，重算检验一。
- 按建筑群大小分层：f_BAG > 0 的像元按 8 连通分成若干连通体，按连通体大小分三层：1–4 个像元（孤立建筑或农舍）、5–50 个像元（小村落）、>50 个像元（聚落）。在每层内计算 f_BAG ≥ 0.25 的像元召回。
- 同样的检验也用在 CNN_I 和 CNN_IG 上。
- 这一部分**不是预注册的**。论文里写成「探索性分析」，只用来解释 §5.2 的结果，不作为独立证据。
